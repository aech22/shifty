シフトひな型（2026-10-01版）の取り込みと機能差分 実装計画

10月前半更新分として届いた xlsm 13本と使い方 PDF を読み、前回（2026-09-26）の取り込み結果＝本番 Firebase との差分、および ① 実装後の Shifty とひな型の機能差分をまとめ、取り込みと機能追加の計画にする。作成 2026-10-01・作成者 Fable 5.1（調査は Opus のサブエージェントが読み取り専用で実施。Firebase・リポジトリへの書き込みは無い）。

最初に知っておくべき事実（調査で確定）

  • ひな型の版が変わった。 13本のうち12本は新しい版（改訂履歴 09-24〜10-01）。「休憩の設定」シートが増え、休憩欄は数式で自動計算される。今の取り込みスクリプトは値を読むので、そのまま使うと全出勤日に日別の休憩上書き（adjustedBreak）が書かれる。
  • 魚えんの「変更後.xlsm」は古いひな型（山田龍太さんが 09-30 12:30Z に保存）。無印の方が新ひな型で、作成者が openpyxl（スクリプト生成・10-01 10:46Z）。変更後にある修正6件が新版に入っていない。
  • 鶏えん2店舗は本番で実運用中。 スタッフの提出・管理者調整・企業への提出記録（09-26）がある。xlsm で上書きするとスタッフの休み希望が消える。
  • 本番のルールと Cloud Functions は P7 まで反映済み（2026-10-01 に主セッションがバイト照合・32関数を確認）。BACKLOG の「未反映」記述は古い。この計画で前提にする Shifty の機能（P3.5a の休憩規則・P3.5b の按分窓・P2 の年間所定）はすべて本番で使える。
  • ① の4件（パスコードの文言削除・企業連携タブからのパスコード変更・労務判定の法人への統合・特定技能の週の公休判定）は、この計画と同じ日に Opus が実装し本番へ出す。本書はそれが済んだ状態を起点にする。

D1. 取り込みは「上書き」ではなく「差分の追加だけ」にする

推奨本番を正とし、xlsm にあって本番に無いものだけを足す。 本番にだけあるもの（スタッフの提出・管理者の調整・手で足した勤務）は消さない。時刻が食い違うセルは一覧で報告し、置き換えはしない。
理由9/26 に投入した sub は全店で手が入っていない（updatedAt なし）が、鶏えん2店舗はスタッフの提出で運用中。現行スクリプトの「期間があればスキップ」では5店舗（京天・梅京・文天・炭イ・魚初）の前半160＋78＋152＋101＋95件がいつまでも入らない。
別案xlsm で丸ごと置き換える（鶏えんの提出が消える）／何も取り込まず手入力に任せる。

D2. 鶏えん2店舗（東通り・3ビル）は今回の取り込みから外す

推奨外す。 差分（時刻違い29件・本番だけの出勤19件・xlsm だけ22件）は一覧を出し、店長の判断で手入力する。
理由本番は企業属性（特定技能・外国人派遣28/40）と派遣元1文字の番号で運用しており、xlsm の区分・「派遣」とは体系が違う（番号24名・属性28名が食い違う）。shop-map.json も confirmed:false のまま。機械的に足すと体系が混ざる。
別案xlsm だけにある勤務（徳田 恵太の炭イ応援10件など22件）だけを足す。ユーザーが指示すれば D1 の規則で対応できる。

D3. 魚えんはどちらのファイルを正とするか

推奨名簿は新版（19名）、シフトは変更後の修正6件を優先して重ねる。 具体的には新版を基に、栗本律 10/5・10/12 の退勤延長、川渕愛梨 10/8 の追加、梅本翔平 10/6・山田龍太 10/8・前川佐登志 10/10 の削除を適用する。
理由変更後は日付が古い（09-30）のに新版に無い修正を持つ。新版は旧データを新ひな型へ機械的に移したものに見える（作成者 openpyxl）。店長の手が入った方を勤務の正とし、名簿は新しい方を取る。
別案新版だけを正とする（6件の修正を捨てる）／店長に確認して1本に直してもらう（確実だが待ち時間が出る）。

D4. 休憩は「手入力のセルだけ」を取り込み、店の規則は Shifty の設定で再現する

推奨数式でないセル（黒太字＝手入力）だけを adjustedBreak に入れる。 店の規則（拘束8h以上1h・6h以上1h・中休み）は各店舗の breakMode=length（basis=binding・inclusive）と idleBreak に投入する（第3部 F1）。
理由全日を上書きで入れると、提出一覧の「手動（太字）」が全員全日に付き、店が規則を変えても古い値が残る。手入力の実数は京天4・ビア1・文天5・文心10・炭三4 だけ。
別案全日の休憩を adjustedBreak で入れる（確実に Excel と一致するが、以後の変更が効かない）。

D5. 名前の表記ゆれは本番の名前に寄せ、本番の名前は変えない

推奨従業員番号（数字）→ 空白と全角半角を正規化した名前 の順で本番の登録に対応づけ、本番の名前をキーに書く。 xlsm だけの表記（空白なし37名・来/來・座/坐・２/2・文心のフルネーム）で改名はしない。対応づかない名前だけを新規スタッフとして足す。
理由名前は sub・settings の8マップ・写し・pay・laborMonths のキー。改名は入口が2つ（StaffTab・CF companyRenameStaff）あり、取り込みで黙って動かすと提出 URL と Cookie の紐付けが切れる。
別案xlsm の表記へ改名する（CF companyRenameStaff を人数分呼ぶ。可能だが今回の目的に不要）。

D6. 本番だけ・xlsm だけのスタッフと、ビアのマリカ7日分

推奨本番だけの人は残す。xlsm だけの人は、本番の keepStaff に「削除済み」の記録がある人（ビア5名・鶏三の池本明央・鶏東の浅野 健斗）を足さず、それ以外（京天のニュー・魚初の応援2名・文心の白根 ほか）は足す。マリカの7日分は残す。
理由keepStaff は管理者が意図して削除した記録。マリカは京天の xlsm では同じ日に京天勤務やビア・魚初への応援になっており、どちらが正か xlsm からは決まらない。消す側に倒さない。
別案xlsm に無い勤務（マリカ7日）を消す／削除済みの人も足す。

D7. 文心（文蔵東心斎橋）に10月の期間を作り、前半・後半を入れる

推奨10月前半・後半の期間を作って取り込む。 本番は9月後半（sub 5）までしか無く、xlsm は唯一後半まで埋まっている（46件）。名前は番号で突き合わせる（9011・511・5・1122・1131 が一致）。後藤の属性は本番（社員）のまま。
理由期間が無いとスタッフ URL が開けない。番号が一致するので対応づけに迷いが無い。
別案前半だけ作る。

D8. 後半（16〜31日）の期間は全店に作る

推奨後半の期間を無い店舗すべてに作る（sub は入れない）。 既にあるのはビア（10-01 作成）と鶏えん2店舗。
理由企業の毎月の固定締切は10日・25日。後半の提出を受けるには期間が先に要る。xlsm の後半が空なのは、まだ埋める時期でないため（ひな型の運用は15日までに本人へ）。
別案店長が作るのを待つ。

D9. 応援の店コードを Shifty の略称に足す

推奨Excel の2文字店コード（京天・梅京・小四・小難・ビア・文天・文心・炭イ・炭三・魚初・鶏三・鶏東）を各店の shopAbbrs に追加する。 既存の略称は残す。新コード「鶏バ」（鶏えん バルチカ03店(仮)）は店舗が無いので登録しない。
理由いま本番の略称と一致するのはビアと鶏三だけ。合わないと応援は「メモ文字」として残り、店舗間の重複判定・ヒートマップ除外・P3.6 の合算が効かない。文天の xlsm は「鶏三17.5」のように15分でない時刻も含むが、TO は15分刻みなので 17:30 で入る。
別案取り込みの変換表だけで吸収する（画面で打つ略称と一致しないままになる）。

D10. 所定・上限の基準をひな型（年2,080h）に揃えるか

推奨法人の労務判定に年間所定 2,080h を入れる（運用）。あわせて Shifty 側で、年間所定があるときは「所定未満」の比較と上限（capMin）を所定（176:39）基準にする（第3部 F4・コード変更）。
理由ひな型は 所定176:39・目安199・上限206（＝所定＋固定残業の切り捨て）。Shifty の P2 は目安だけを所定基準に変え、上限と「所定未満」は総枠（177:08・上限207:08）のまま。同じシフトで Shifty は上限を 1h08 甘く判定する。
別案運用（年間所定の投入）だけ行い、上限は総枠基準のままにする（1時間強の差を承知で残す）。

D11. 「入力の問題」の警告を Shifty に足すか

推奨足す（第3部 F6）。 片側だけの日・読めない文字（例「事務11」）を労務の確認パネルに「入力の確認」として出す。要修正にはしない。
理由Shifty は片側セルを候補時間で補完し、読めない文字はメモとして保存する＝黙って通る。ひな型は約30件を「入力の問題」として要修正にしている。店長が同じ基準で見られるようにする。
別案補完とメモの設計を信じて警告を足さない。

D12. 人数チェック（確認時刻・担当別）を実装するか

推奨今回は実装しない（BACKLOG に理由と再着手条件を書く）。 再着手条件は、担当（ホール・キッチン・両方）と必要人数が3店舗以上で運用に使われたとき。
理由xlsm の担当欄は3店舗（計7名）、必要人数は2店舗にしか入っておらず、ひな型でも大半の店で動いていない。Shifty には既に必要ポジション（matchPositionSlots）と PDF の昼夜人数（headcountAt）がある。
別案headcountAt を画面にも出す（小さい）／ひな型と同じ確認時刻方式の「不足・多い」を作る（大きい）。

第2部必須項目 — 取り込みの差分更新（shifty-shift-import の改修）

目的

新ひな型の xlsm を読み、本番を壊さずに「足りないものだけ」を入れる。手順は shifty-shift-import スキルに残し、来月以降も同じ手で回せるようにする。コードを変えるのはスキルのスクリプト（~/.claude/skills/shifty-shift-import/scripts/）だけで、Shifty 本体のコードは第3部で扱う。

受け入れ条件

  • A1 新ひな型の検出。 extract_xlsm.py が「休憩の設定」シートの有無で版を判定し、新版では休憩欄を data_only=False で読み直して数式のセルは brk_h を null、手入力のセルだけ値にする（D4）。旧版（魚えん 変更後）は従来どおり値を読む。版と手入力件数を出力に書く。
  • A2 店の休憩規則の抽出。 「休憩の設定」シートの 8h/6h の段・中休み（全日／平日のみ／なし・出勤≦／退勤≧・時間）を店舗ごとに JSON に出す。第3部 F1 の設定投入の入力になる。
  • A3 本番との差分計算。 新スクリプト diff_against_prod.js（読み取り専用・Admin SDK の once だけ）が、店舗ごとに ①名簿の対応表（番号一致→正規化名一致→未対応）②番号・属性・所属店舗の差 ③人×日のセル差分（xlsm だけ／本番だけ／時刻違い／メモ違い／休憩違い）を出す。D5 の対応規則をここに固定し、build_payload.py はこの対応表で本番の名前をキーにする。
  • A4 ペイロードは「追加」だけ。 build_payload.py --mode=add が、xlsm だけにあるセル・未対応の新規スタッフ・無い期間だけをペイロードにし、本番にあるセルには触れない（D1）。鶏えん2店舗は --skip で外せる（D2）。魚えんは --overlay=変更後.xlsm で修正6件を重ねられる（D3）。keepStaff に載っている人は足さない（D6）。
  • A5 期間の作成。 文心の10月前半・後半と、他店の後半を作る（D7・D8）。ID・urlToken・tokens 逆引きは import_to_firebase.js の既存の形。企業の提出期限（期間キー）は CF の毎月の固定締切に任せ、ここでは書かない。
  • A6 休憩の取り込み。 手入力の休憩だけ adjustedBreak（分）に入れる。自動計算の休憩は入れない（D4）。
  • A7 応援の略称。 店コードを shopAbbrs に追加するペイロードを別ファイルで出す（D9・settings への追記なので差分 update）。重複チェック（他店と同じ略称・予約語 h/k/x・/）は isReservedShopAbbr を本体から読む。
  • A8 ドライラン → 承認 → 書き込み。 何をどのパスに書くかの一覧（店舗・パス・件数）を出して止まり、ユーザーの承認後に --write。コレクションの全体 set は一度もしない（CLAUDE.md の periods・subs の規則）。
  • A9 報告。 取り込めなかったもの（時刻違いの一覧・本番だけのスタッフ・鶏えんの差分一覧・片側だけの日・「事務11」）を店舗ごとに列挙する。
  • A10 スキル文書。 SKILL.md に「新ひな型」「差分モード」「鶏えんの扱い」「魚えんの2本」を追記し、shop-map.json の confirmed と「鶏バ」の注記を更新する。

第3部必須項目 — ① 実装後の Shifty とひな型の機能差分

差分の全体表

ひな型（2026-10-01版）が持つ機能を、① 実装後の Shifty と突き合わせた。「設定」は Shifty のコード変更なしで運用の投入だけ要るもの、「コード」は実装が要るもの、「同等」は既にあるもの、「見送り」は第1部で見送りを推奨したもの。

ひな型の機能ひな型の規則Shifty（① 後）区分
店の休憩（2段）拘束時間で判定・「以上」・8h→1h・6h→1h（全店同じ）P3.5a の breakLength basis=binding・tiers inclusive で表せる。本番は全店が 15〜17時の時間帯方式のまま設定（F1）
中休み出勤≦14.5 かつ 退勤≧17 → 2h（店で値が違う・平日のみ／全日）P3.5a の idleBreak で同じ形設定（F1）

手入力の休憩黒太字＝自動に優先。「休憩を自動に」で戻すadjustedBreak と「自動に戻す」（breakDecisionOf）同等

目的

受け入れ条件

F1 休憩規則の投入（設定・運用）

  • 11店舗（ビアは企業外なので店舗の設定タブで個別に）の breakMode を length にし、breakLength を basis=binding・tiers=[{overMin:480,breakMin:60,inclusive:true},{overMin:360,breakMin:60,inclusive:true}] にする。
  • idleBreak を店ごとの表（京天・梅京・文天: 全日 14:30／17:00→120分、小難: 全日 12:00／17:00→120分、文心: 全日 14:30／17:00→165分、小四・炭三・鶏三: 平日のみ 14:30／17:00→120分、ビア・炭イ・魚初・鶏東: なし）で入れる。
  • 投入前に、小四の 10/3 の1人（xlsm の自動休憩が1h の日）で Shifty の getBreaksFor が同じ60分を返すことをユニットテスト（既存の P3.5a テストに値を足す）で確かめる。
  • 既存の breakTimes（15〜17時）は残すか消すかをユーザーに確認する（length 方式では読まれないので残しても結果は変わらない）。

F2 残業と目印の設定（設定・運用）

  • 企業の共通設定の属性「特定技能」（co_Hzxk84Qv）に otProrate={window:"halfMonth",fixedMin:900}（15h）を入れる。
  • B 制の店舗で showDailyOverB=1、判定対象外の目印 highlightExternalOver8h=1・externalOverThresholdMin=480 を店舗の設定タブで入れる（ひな型の「外部の8h超は赤」に対応）。
  • 法人の労務判定に annualScheduledMin=124800（2,080h）を入れる（① で労務判定は法人側に統合済み）。

F4 上限と「所定未満」を所定基準にする（コード）

  • laborMonthFrame に、年間所定があるとき capMin を FLOOR(所定上限＋固定残業)（時間の切り捨て＝206h）にする分岐を足す。無いときは従来の総枠＋固定残業のまま（1バイトも変わらない）。
  • guideStatusOf の「所定未満」の比較を、年間所定があるときは所定上限（176:39）と比べる。無いときは総枠。
  • テスト: 2,080h・10月（31日）で 所定176:39・目安199・上限206 を手計算の期待値として固定（ひな型の値）。未設定の既存テストが変わらないこと。
  • CLAUDE.md の P2 の節「上限（capMin）は変えない」を実態に直す。

F6 入力の確認（コード・要修正ではない）

  • laborFindingsFor に要修正でない finding（例 key inputCheck）を足し、①出勤・退勤の片側だけの日（補完が効いた日）②時刻でもコマンドでもない文字だけの日（メモだけ・例「事務11」）③A/B の人で従業員番号が空か「派遣」 を「入力の確認n日（…）」で出す。OVERALL_FIX_KEYS・LABOR_DAY_FIX_KEYS には入れない。
  • 判定対象外（none）の人にも①②は出す（時刻の入力ミスと同じ扱い）。
